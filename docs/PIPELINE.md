# 处理路径与研究入口

## 宾得：执行原厂程序

`native_host.py` 加载 DCU 5.10.2.2，核对文件版本，建立所需的运行环境和导入地址。桌面界面入口不执行。原厂文件的校验值固定在代码中，遇到其他版本会停止，避免把旧地址用到新程序里。

`native_controls.py` 负责原厂默认参数对象与调参函数：

- `0095b0 → 06c910`：默认参数构造。
- `0090e0`：选择模式和对应默认记录。
- `007370`：将界面对象中的控制参数送入原厂处理。

`native_worker.py` 用原厂上层调度入口处理图像：PEF 使用 `abf2a0`，RGB 兼容输入使用 `adcbd0`。RGB16 加填充的原厂工作格式保留到 TIFF16 输出，避免经过默认的 8 位显示格式。调用地址都是指定版本的 RVA。

`native_backend.py` 负责文件输入、参数银行、子进程、取消和输出读取。其他品牌 RAW 经 LibRaw 解码，再送入 RGB 兼容路径；手动调过或 AI 降噪后的照片也进入这条 RGB 路径。未修改的原生 PEF 全尺寸处理保留 RAW 入口。

`native-data` 只保留处理所需的精简参数标签。原始照片、作者、GPS、相机序列号和工作日志不随源码发布。

## 理光：三种输入，同一套色彩阶段

`gr4_renderer.py` 明确区分 `linear`、`srgb`、`standard`。普通 sRGB 输入做标准传递函数解码；只有明确标记为理光 Standard 成片时才走 Standard 反解。RAW 解码得到的线性值直接进入色彩计算。

处理顺序是模式矩阵、分色相、曲线、后级矩阵、显示色度处理。`gr4_parameters.py` 从原厂表生成动态影调曲线和饱和度矩阵，参数按模式校验。它与 CPU / GPU 内核共享配置，默认表的旧版验证样本保留在 `gr4-data/verification.npz`。

`gr4_core.c` 是原生 CPU 实现，`gr4-core/photo_kernels.cl` 是 OpenCL 实现。两者保留双精度计算及相同求值顺序。设备先通过精度检查，再比较处理时间；GPU 不适用时退回 CPU。

## 照片编辑和降噪

`editor_pipeline.py` 的顺序是输入降噪、照片手动调整、选定滤镜。`photo_edit.py` 保存参数历史，`photo_denoise.py` 按照片与模型缓存完整尺寸结果。左侧风格卡片使用独立的缩略图缓存。

`startup_prewarm.py` 在启动后准备默认或上次使用的 AI 模型。它与真实推理共用 `neural_process.py` 的常驻进程和会话。相同模型的真实任务接着使用预热结果；其他模型的任务取消旧预热。预热只使用模型校验样本，照片文件在这一步没有参与。

模型切换释放旧模型的工作空间，避免两个大模型长时间一起占显存。CPU 与 GPU 精度、测速仍在后台模型进程中完成。SCUNet 已从当前版本移除。

## 验证范围

本次新增的输入、参数和计算路径见 `verification/gr4-controls.json`。`raw-routing.json` 记录佳能 CR2 的输入路由检查，`warmup.json` 记录常驻模型准备和复用耗时。

宾得原厂函数调用和跨品牌输入适配分开记录。后续对照集需要固定同一张输入、同一设置、同一原厂版本，再比较图像。理光也需要真机同 RAW 开发结果来核对尚未实现的硬件阶段。
